Security & privacy

A summary of Vexunori's threat model: what we try to protect, from whom, and where the protection stops. The source code and its technical documents are not public; this page is the public summary.

No external audit has been performed. Vexunori uses established, reviewed cryptography libraries (nostr-tools, the @noble libraries, the browser's WebCrypto), but the app as a whole has not been independently reviewed. Do not rely on it where a mistake could put someone in danger.

What we protect

  • Message contents — text, reactions, edits, attachments, group names and workspace data.
  • Your secret key — the key that is your identity and decrypts your messages.
  • Your local data — messages, contacts, Vault items and settings stored on your device.
  • Who talks to whom — partly. Sender identity is hidden from relays; the recipient is not. See the metadata table.

Who we consider

Relay operators
Store and forward encrypted envelopes. Cannot read them, but see recipient keys, timing, sizes and IP addresses, and may keep data as long as they like.
Network observers (Wi-Fi owner, ISP, state)
See that you connect to relays, when, and how much data flows. Connections use TLS (wss://), so they do not see envelopes.
Other participants
Read what you send them by design. They can screenshot, copy, forward or ignore delete requests.
Device thieves
Get your phone or computer. Protected by local encryption when the app is locked and you use a passphrase; not protected if the app is unlocked or you chose the web "device" key mode.
Malicious contacts
Send spam, harmful files or misleading links. Message requests, blocking, SendGuard and the link inspector help; they are not a malware scanner.

Known limits

  • No forward secrecy. NIP-44 does not provide it. Someone who stores envelopes and later steals your secret key can read them.
  • Metadata is visible to relays, as described above. Use several relays, Tor on Android, or your own relay to reduce what one operator learns.
  • Delete and disappearing messages are honoured by cooperating apps only.
  • The web app is delivered by a web server. Whoever controls the server could deliver modified code. The Android app avoids this for the code it ships: an installed APK changes only when you install an update signed with the same key.
  • The source code is not public and has not been audited. Vexunori is free to use but not open source, so nobody outside the project can currently review its code. The cryptography comes from open-source libraries (nostr-tools, @noble/*, WebCrypto); how the app uses them cannot be checked independently. See the licence page.
  • Not yet tested on real Android hardware. The 0.1.0 APK was built and checked by automated tests, but has not been run on a phone or an emulator.
  • Contacts added only by their public key (npub) may not receive your messages: Vexunori does not look up their inbox relays (NIP-17 kind 10050 lists), so it sends to your own relays. Add contacts with their invite link or QR code, which includes their relays.
  • No protection against a compromised device (malware, a hostile OS, a stolen unlocked phone).
  • Every feature's status and limits are on the Features page.

Report a vulnerability

Please report security problems privately rather than in a public issue. The maintainer has not yet published a dedicated private security contact. Until one is listed here, do not post exploit details publicly; instead ask for a private channel through the contact route given at the end of the licence text, without technical details.

We do not run a bug bounty and cannot offer payment.
