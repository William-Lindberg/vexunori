Group workspaces

Every group has a shared workspace: tasks (with assignment and completion), to-do lists, polls, notes, events, links, file references and bookmarked messages. Personal reminders sit next to it but stay on your device and are never sent.

How sync works

There is no workspace server. Each change is a small operation, signed by its author and sent to all members end-to-end encrypted, the same way as group messages. Each member's app builds the workspace from the operations it has.

  • Offline changes are saved on your device first and sent when you are back online. The workspace shows which of your changes have not been sent yet.
  • Duplicates (the same change received twice) are ignored.
  • Late joiners ask members for the workspace history; members whose copy differs send it.
  • Only current group members can change the workspace. Items can be deleted by their creator or an admin. Only they can also close or reopen a poll, change a poll's question, or change a saved link's address.

Notes you edit together

Everyone in the group can open a note and write in it at the same time. Changes made at the same time are merged, character by character, so nobody's typing is lost and there is no "conflict copy".

  • Formatting: start a line with # for a heading, wrap words in **bold** or *italic*, start a line with - for a list and - [ ] for a checklist item. The toolbar buttons (B, I, H, list, checklist) add these marks for you, and Ctrl+B / Ctrl+I work too. Pressing Enter in a list continues it.
  • Checklists: in the note's view, tick a box to mark the item done (- [x]). Everyone sees the tick.
  • While you type, your changes are collected and sent to the group about once a second. Other members see them when their app receives them; this is not a live keystroke stream.
  • Status: under the title you see "Saved on this device, not sent yet", "Sent, not yet accepted by a relay" or "Sent, accepted by a relay" for your own changes, and who else edited the note recently. "Accepted by a relay" does not prove that every member has the change yet.
  • Missing changes: when you open a note, your app asks the other members for anything of that note it has not received (at most every 10 minutes). Members answer with only the missing part.
  • Size: a note can hold up to 100 000 characters. Big changes are split into several encrypted messages.
  • Older notes (made before shared editing) are converted the first time someone opens them. A note that had two conflicting versions can still be resolved the old way, or opened for shared editing, which keeps both versions in the text under "--- Version" lines.
  • Any member can change or remove any text in a note. Each change is signed, so the app knows who made it, but it does not show who wrote which word.

Conflicts

  • Two people change the same field (for example a task title) at the same time: every app picks the same winner (the later change by a hybrid logical clock) and the other value is replaced. That is a deliberate trade-off for short fields; the clock order is not always real-time order when device clocks disagree.
  • Two people edit the same note at the same time: both changes are merged into the text (see above). Only notes from older app versions can still show a conflict.
  • Poll votes: each person has one vote per poll; their latest one counts.
  • To-do entries added at the same time are both kept.

Limits

  • Two members only see the same workspace once both have received the same changes. If a relay lost a message, the next sync request repairs it.
  • A device with a wrong clock can win conflicts it should lose (clocks too far in the future are rejected).
  • File items in the workspace reference files sent through chat (same 1.5 MB limit).
  • Personal reminders fire only while Vexunori is open and unlocked; one that falls due while the app is closed shows as missed after you unlock. On Android they are also scheduled as local notifications that can fire while the app is closed, possibly a few minutes late. With the "Full" notification preview, the reminder text is handed to Android and stored there unencrypted until it fires.
  • Note changes from someone still using an older app version are not merged into a note that has been opened for shared editing.
  • The workspace history is never compacted: every change is kept on each member's device, so it grows over time.
  • Workspace changes are signed so they can be passed on to late joiners. A member who leaks one can prove you wrote it, unlike chat messages.
