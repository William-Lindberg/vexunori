Tor

Tor hides your IP address from the relays you connect to. It does not hide your public key, and it does not protect against timing analysis or a compromised device.

The Android app has Tor built in: you do not need Orbot or any other app. Built-in Tor and the Private Browser are new in 1.0.0 and have not yet been tested on a real device.

Built-in Tor on Android Experimental

  1. Open Settings → Tor and choose Prefer Tor or Tor only (strict).
  2. Under Which Tor, keep Built-in Tor (recommended).
  3. Vexunori starts Tor inside the app. A progress bar shows how far it is. Connecting to Tor can take up to a minute, longer on slow networks.
  4. When Tor is ready, Vexunori tells Android System WebView to send all of the app's web traffic — relay connections and checks — through Tor, and then runs a Tor check.

The status says Tor confirmed only after the check sees your traffic leaving from a Tor exit. Until then it says "Connecting to Tor… 45%", "Checking", "Not using Tor" or "Tor check failed" — never a decorative onion icon. If Tor fails, the app says so; it never quietly switches to a direct connection in strict mode.

With Tor mode on, Tor starts automatically every time you open the app. New identity asks Tor for new circuits, so relays see a different Tor exit. This needs an Android System WebView that supports proxy override; the Tor settings tell you if yours does not. The built-in Tor makes the APK about 20–30 MB larger. It does not support bridges yet.

Advanced: use Orbot instead

If you already run Orbot, choose Advanced: use Orbot instead. Vexunori then uses Orbot's HTTP proxy (default 127.0.0.1:8118). You start and connect Orbot yourself. Orbot is also the way to use bridges where Tor is blocked.

Prefer vs strict

Prefer Tor
Uses Tor when possible. While Tor is still connecting, or if it fails, Vexunori connects directly and shows "Tor not confirmed".
Tor only (strict)
No relay connections at all until a check confirms Tor. If Tor stops, connections fail and messages wait in the queue. Calls are disabled, because their audio/video cannot go through Tor.

What goes through Tor

  • Through Tor (when confirmed): relay connections, the Tor check.
  • Always through Tor: the Private Browser, whether or not Tor mode is on.
  • Not through Tor: links you open in your normal browser; calls (disabled in strict mode); parcel files shared via other apps; traffic from Android itself and other apps.

The Tor check contacts check.torproject.org, and as a fallback api.ipify.org (to learn the public address) and onionoo.torproject.org (to look it up in the Tor relay list). Checks run only while Tor mode is on or when you press "Check now".

Tor mode protects Vexunori's own connections. The app's WebView is not Tor Browser and does not have its anti-fingerprinting protections.

Private Browser · via Tor Experimental

On Android, the Browser page opens web pages and .onion sites through the built-in Tor. It runs in its own process, separate from your chats and Vault, and loads nothing if Tor is not ready. If Tor mode is off, the Browser page can start Tor just for the browser; your chats keep connecting directly.

Use the address field, or the quick buttons: a Tor connection test (check.torproject.org) and DuckDuckGo as an onion service. Anything that is not a web address is refused with a hint — nothing is searched for you behind your back. In the Link Inspector, Open in Private Browser (Tor) opens a link there.

Security levels

Standard
JavaScript on and all protections on. WebGL and WebRTC are always blocked.
Safer (default)
JavaScript on, but WebAssembly, web workers and WebGL are blocked too.
Safest
JavaScript off. The strongest option; many sites look plain or do not work.

What the Private Browser protects

  • WebRTC is blocked, so a page cannot leak your real IP address through it.
  • A uniform user agent that matches the real browser engine.
  • Rounded window and screen sizes (letterboxing).
  • Timezone set to UTC and language to en-US.
  • Fixed hardware values.
  • Canvas readback blocked; WebGL and audio fingerprinting blocked.
  • Reduced timer precision.
  • Sensors, battery, Bluetooth, USB and similar device APIs removed.
  • HTTPS only (except .onion sites), with a warning before any insecure page.
  • Each site gets its own Tor circuit (stream isolation).
  • Third-party cookies off; everything is wiped when you close the browser and on New identity.
  • Google Safe Browsing and WebView metrics turned off, so no address lookups leave outside Tor.
  • Downloads, camera, microphone and location blocked; screenshots blocked.

What it can't fully hide

  • The browser engine (Android System WebView) can still be identified.
  • Font measurement tricks.
  • The TLS fingerprint of the connection.
  • The system language may still appear in some background requests.
  • Very determined sites may still tell devices apart.

It is not Tor Browser. It has its own anti-fingerprinting, but it cannot match Tor Browser's, so sites may still recognise this device. For the strongest protection use the official Tor Browser from the Tor Project (torproject.org/download).

Web browsers

A website cannot run Tor or send its own traffic through Tor. In a normal browser, Tor mode is unsupported and the built-in Tor option is shown as "Android app only". If you open the web app in Tor Browser, Vexunori can detect that and shows "Tor confirmed (this browser)"; strict mode then works too. The Private Browser is not available on the web; the Browser page links to the official Tor Browser instead.

Troubleshooting

  • Stuck at "Connecting to Tor": check your internet connection and wait up to a minute. Switch Tor mode off and on to restart Tor. Where Tor is blocked, use Orbot with bridges.
  • "Tor check failed" right after connecting: the first circuits can be slow. Press "Check now" again.
  • With Orbot: "Not using Tor" means Orbot is not running or connected, or its HTTP proxy port does not match the setting.
  • Some relays block Tor exits. Add relays that accept Tor if messages stay queued.
