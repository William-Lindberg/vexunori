Files & SendGuard

SendGuard runs before a file or link leaves your device — in a chat, a group workspace, an export or the share sheet. It runs entirely on your device: nothing is uploaded and nothing is fetched.

What SendGuard checks in files

  • Type: what the file name says vs what the content actually looks like (for example a ".pdf" that is really a program).
  • Name: names that may reveal something (real names, dates, double extensions like photo.jpg.exe).
  • Metadata: for example camera model, date and GPS location in photos, author fields in documents, where it can read them.
  • Size against the attachment limit (1.5 MB per file in chats).

You then choose: send as is, send a stripped copy where Vexunori can remove the metadata (common image formats), or cancel. The original file is never changed.

SendGuard is not a malware scanner and metadata removal is not guaranteed to be complete: some formats hide information in places it cannot read, and the content itself (a face, a street sign in a photo) is never checked. Very large files are only partly scanned.

The link inspector

Links in chats do not open directly. The inspector first shows:

  • the real destination host, decoded from punycode, with a warning when it mixes alphabets (look-alike domains);
  • whether the visible text and the real link point to different places;
  • tracking parameters (like utm_…), which Vexunori can strip;
  • unusual schemes and plain http:// links.

When you confirm, the link opens in your normal browser, outside Vexunori. Vexunori does not fetch link previews, so the website does not learn about the link until you open it. Your browser then handles cookies, certificates and downloads as usual, and does not go through Tor unless your browser itself does.

Privacy receipts

Each share, external link and export is noted in a local, encrypted log in the Privacy Center, so you can review what left your device. It is never sent anywhere and you can clear it.
